# Repository Guidelines

## Project Structure & Module Organization

This is a Python 3.10 automation project for Onmyoji. Core reusable code lives in `module/`, including device control, OCR, config, server, GUI, and shared base utilities. Task implementations live in `tasks/<TaskName>/`, usually with `config.py`, `assets.py`, `script_task.py`, and task-specific image/OCR/click assets under nested folders. Entry points are `gui.py` for the desktop UI, `server.py` for the FastAPI service, and `script.py` for script orchestration. Runtime configuration and generated state belong in `config/` and `log/`; do not commit local logs or user secrets. Development helpers are in `dev_tools/`, deployment assets in `deploy/`, and bundled external binaries in `bin/`.

## Build, Test, and Development Commands

Run commands from the repository root.

- `python -m pip install -r requirements.txt`: install pinned runtime dependencies.
- `python gui.py`: start the local GUI and OCR server.
- `python server.py --host 0.0.0.0 --port 22270`: start the web service.
- `docker compose build`: build the Docker image from `deploy/docker/`.
- `docker compose up`: run the containerized service with the repo mounted at `/app/OnmyojiAutoScript`.
- `python dev_tools/generate_requirements.py`: regenerate `requirements.txt` from `requirements-in.txt` after dependency changes.

## Coding Style & Naming Conventions

Use 4-space indentation, UTF-8 source files, and explicit imports. Follow existing module patterns before adding new abstractions. Task folders use PascalCase (`RealmRaid`, `DemonEncounter`), while image and JSON asset names are lowercase, task-prefixed, and descriptive, such as `demon_de_find.png` or `image.json`. Keep user-facing text compatible with `assets/i18n/` when adding labels.

## Testing Guidelines

There is no dedicated test suite in this repository yet. Validate changes with the narrowest runnable path: import touched modules, run `python gui.py` or `python server.py`, and exercise the affected task against a configured emulator/device. For asset changes, verify screenshot matching and update related `image.json`, `ocr.json`, or `click.json` files together.

## Commit & Pull Request Guidelines

Recent history uses Conventional Commit-style messages, for example `fix(RealmRaid): ...`, `docs(workflow): ...`, and `chore(workflow): ...`. Keep commits scoped to one behavioral change. Pull requests should describe the affected task/module, list manual verification steps, link related issues, and include screenshots or logs for UI, image-recognition, or task-flow changes.

## Agent-Specific Instructions

Respond in Simplified Chinese when interacting with users. Prefix shell commands with `rtk` where the local environment requires it. If adding project skills, keep the source in `.agents/skills/<skill-name>/SKILL.md` and expose it through relative symlinks instead of duplicating files.
Before working on Windows/OASX/MuMu integration, FindJade small-account flows, or real-device validation, use the project skill at `.agents/skills/oas-windows-dev/SKILL.md`.

## Local SubAccountRotation Setup

`SubAccountRotation` is a local MVP task for small-account orchestration. It is intentionally implemented as a normal task under `tasks/SubAccountRotation/` and does not inject hooks into `script.py` or the global scheduler. Configure it with `python scripts/configure_subaccount_rotation.py --config config/oas_findjade.json`; by default the helper keeps the scheduler disabled and enables only the `LoginOnly` sub-task. Use `--enable --run-now` only for explicit validation, and prefer `--max-accounts-per-run 1` for first real-device checks. Pass `--disable-find-jade` during isolated validation if `FindJade` is already enabled, otherwise the global scheduler may continue into the old `FindJade` task after `SubAccountRotation` finishes. The implemented adapters are currently `Orochi`, `FindJade`, `MysteryShop`, `DailyTriflesStoreSign`, `Hunt`, `TalismanPass`, `Exploration`, and `AreaBoss`; keep new adapters opt-in and validate one sub-task at a time before enabling real use. `MysteryShop` was implemented from an earlier misread and is not the user's intended shop-daily feature. `AreaBoss` is code-level implemented but still pending real-device validation.

## Local WantedQuests Main Setup

For the main-account cooperation closure, run `python scripts/check_wanted_quests_main.py --config config/oas_main.json` from the repo root to verify that `WantedQuests` is enabled and schedulable. ## Local Patch Behavior Notes

- `tasks/base_task.py` intentionally does not schedule `WantedQuests` for every accepted friend invitation. It only schedules `WantedQuests` after accepting a recognized cooperation popup: jade, cat food, or dog food, based on existing `GlobalGameAssets` rules. Plain team invites must keep their original accept behavior without touching `wanted_quests.scheduler.next_run`.
- The cooperation scheduling patch writes `WantedQuests.next_run` with `server=False` so it becomes pending immediately. Do not replace this with the default server-time scheduling unless the goal is to delay execution to the next server update window.
- This local patch does not force disabled tasks to run and does not change `module/config/config.py`, `script.py`, or global scheduler semantics. `WantedQuests.scheduler.enable` must be true in the main-account config, and `scripts/check_wanted_quests_main.py --fix` is the explicit helper for enabling/initializing that scheduler section.
- Current cooperation popup detection covers only the existing global invitation assets: jade, cat food, and dog food. Sushi and gold cooperation should not be marked supported until corresponding global popup assets are captured and added.
- For small-account orchestration, the current SDD direction is to add a normal `SubAccountRotation` task instead of injecting hooks into `script.py`; keep this patch line unless intentionally trading easier upstream rebases for deeper scheduler integration.
- `SubAccountRotation` must not call the full existing `FindJade.run()` task, because it has its own small-account loop. `FindJade` remains a standalone task, and `scripts/configure_subaccount_rotation.py --disable-find-jade` is only a validation helper to prevent two independent loops from running in the same scheduler pass.
- `SubAccountRotation` can run `FindJade` through `tasks/FindJade/script_task.py::run_current_account`, which executes the current logged-in account's cooperation-only `WantedQuests` flow without starting the old `FindJade.run()` small-account loop. For isolated validation, enable only `SubAccountRotation` sub-task `FindJade`, pass `--disable-find-jade`, and make sure main config `WantedQuests.scheduler.enable` is true before expecting the main account to consume cooperation invites.
- `SubAccountRotation` can run `Orochi` as a thin current-account adapter. The adapter requires `orochi.orochi_config.user_status = leader` and `orochi.invite_config.friend_1` to be set, then calls the existing `tasks/Orochi/script_task.py` flow. It intercepts `set_next_run("Orochi", ...)` so the ordinary `Orochi.scheduler.next_run` is not changed by a sub-account rotation run; rotation history remains under `sub_account_rotation.history_list_*`.
- `SubAccountRotation` `Orochi` adapter passed Windows real-device validation on 2026-06-07 with one small account inviting main account `不知庭院` and completing one御魂 run. During isolated validation, `restart.harvest_config.enable_courtyard_affairs` may be temporarily disabled if 庭院事务 blocks the one-shot adapter check, but normal configs should keep it enabled and restore it after validation.

Do not call full `DailyTrifles.run()` for this sub-task, because that could trigger summon, friendship, luck message, or sushi purchase behavior. The previously implemented `SubAccountRotation -> MysteryShop` adapter may remain dormant as historical/local code, but it must not be counted as satisfying the shop daily gift requirement or enabled as a substitute.
